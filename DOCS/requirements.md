## 1. プロジェクト概要

### 1.1 背景と課題

現状、個人のスケジュール管理は市販のカレンダーアプリや手書きのメモに頼っているが、以下の課題が生じている。

- 予定の**進行状況（着手済み・完了）が一目で分からない**
- 複数日にまたがる予定が視覚的に把握しにくい
- PC・スマートフォン双方で快適に操作できるツールが少ない

これらの課題を解消するため、**ステータス管理機能を持つオリジナルのスケジュール管理アプリ**を開発する。

### 1.2 目的

イベント・予定を日付ベースで登録・管理できるスケジュール管理アプリを構築する。  
カレンダー形式で予定を視覚的に把握し、ステータス管理によって予定の進行状況を追跡できることを目的とする。

### 1.3 期待効果

- 予定の抜け漏れを防ぎ、当日・翌日にやるべきことを即座に確認できる
- 「予定 → 進行中 → 完了」のステータス遷移により、タスク消化の達成感を得られる
- PC・スマートフォンどちらからも快適に操作できる

### 1.4 利用者

- **利用者**: 開発者本人のみ（個人利用）
- **同時利用人数**: 1名
- **認証**: 不要

### 1.5 開発フェーズ

| フェーズ | 内容 | 技術 |
|---|---|---|
| Phase 1 | バニラJSプロトタイプ | HTML / CSS / JavaScript / localStorage |
| Phase 2 | フルスタック実装 | React + TypeScript / Spring Boot + PostgreSQL |

## 3. 機能要件

### 3.1 イベント管理（CRUD）

#### 3.1.1 イベント作成（Create）

- 新規作成ボタンからモーダルフォームを開いて入力できる
- カレンダーの日付セルをクリックすると、その日付が開始日に自動入力された状態でモーダルが開く
- 入力後、保存ボタンで登録される

#### 3.1.2 イベント参照（Read）

- カレンダービュー：月間グリッド形式で、各日にイベントチップとして表示
- リストビュー：開始日の昇順でイベントを一覧表示
- ステータスフィルターで絞り込み可能

#### 3.1.3 イベント更新（Update）

- カレンダーのイベントチップ、またはリストの編集ボタンからモーダルを開いて編集できる
- 全項目を変更可能

#### 3.1.4 イベント削除（Delete）

- リストビューの削除ボタンから削除できる
- 削除前に確認ステップを設ける（誤操作防止）

### 3.2 イベント項目

| 項目名 | 型 | 必須 | 説明 |
|---|---|---|---|
| タイトル | 文字列（最大100文字） | ✓ | イベントの名称 |
| 説明 | 文字列（最大500文字） | — | 詳細メモ |
| 開始日 | 日付（YYYY-MM-DD） | ✓ | イベント開始日 |
| 終了日 | 日付（YYYY-MM-DD） | — | 複数日イベントの終日。省略時は開始日のみ |
| 開始時刻 | 時刻（HH:MM） | — | 省略時は「終日」扱い |
| 終了時刻 | 時刻（HH:MM） | — | 開始時刻を入力した場合に設定可能 |
| ステータス | 選択肢 | ✓ | 予定 / 進行中 / 完了（デフォルト: 予定） |

### 3.3 ステータス定義

| 値 | 表示名 | 説明 |
|---|---|---|
| `planned` | 予定 | まだ開始していない予定 |
| `in_progress` | 進行中 | 現在進行中のイベント |
| `completed` | 完了 | 終了したイベント |

### 3.4 カレンダービュー

- 月間グリッド（7列 × 最大6行）を表示する
- 前月・翌月へのナビゲーションボタン（‹ ›）と「今日」ボタンを設ける
- 各日のセルに、その日に該当するイベントをチップ形式で表示する
  - 複数日イベント（終了日あり）はすべての該当日に表示する
  - 1セルに最大3件表示し、超過分は「+N more」と表示する
- 今日の日付を視覚的にハイライトする
- ステータスフィルターによる絞り込みが反映される

### 3.5 リストビュー

- すべてのイベントを開始日の昇順で一覧表示する
- 各イベントカードに以下を表示する
  - タイトル
  - 日付（終了日がある場合は「開始日 〜 終了日」形式）
  - 時刻（終日の場合は「終日」と表示）
  - ステータスバッジ
  - 説明（入力されている場合）
  - 編集・削除ボタン
- ステータスフィルターによる絞り込みに対応する

### 3.6 ステータスフィルター

- 「全て / 予定 / 進行中 / 完了」の4つのタブで絞り込みができる
- カレンダービュー・リストビューの両方に適用される

### 3.7 ドラッグ&ドロップによるイベント移動

- カレンダービュー上で、イベントチップを別の日付セルへドラッグして開始日を変更できる
- 複数日イベント（終了日あり）の場合、開始日〜終了日の期間を保ったまま移動する（日数差を維持）
- ドラッグ中は元のセルを薄く表示し、ドロップ可能なセルをハイライトする
- ドロップ後は即座に保存される（Phase 1: localStorage更新、Phase 2: PUT /api/events/{id} を呼び出し）
- Phase 1（バニラJS）では HTML5 Drag and Drop API を使用する
- Phase 2（React）でも同様に HTML5 Drag and Drop API を使用する（外部ライブラリ不使用）

## 5. 非機能要件

### 5.1 レスポンシブ対応

| 画面幅 | 動作 |
|---|---|
| PC（768px 以上） | カレンダービューをデフォルト表示 |
| スマホ（767px 以下） | リストビューをデフォルト表示（カレンダーへの切替は可能） |

- タップ操作を考慮し、ボタン・タップ領域は最小 44 × 44px を確保する
- スマホではモーダルを画面下からスライドアップ表示、PCではセンター表示とする

### 5.2 データ永続化

| フェーズ | 方式 |
|---|---|
| Phase 1 | localStorage（ブラウザ内保存） |
| Phase 2 | PostgreSQL（Docker コンテナ） |

### 5.3 パフォーマンス

- 通常の個人利用（イベント数 〜 数百件）において、表示・操作がスムーズに動作すること

### 5.4 セキュリティ

- 個人利用かつローカル環境での動作を前提とするため、認証・認可機能は実装しない
- Phase 2 のバックエンドは `localhost` のみからのアクセスを許可する（CORS設定）

## 8. REST API 設計（Phase 2）

| メソッド | エンドポイント | 説明 | レスポンス |
|---|---|---|---|
| GET | `/api/events` | イベント一覧取得（`?status=`・`?month=YYYY-MM` でフィルタ可） | 200 + イベント配列 |
| GET | `/api/events/{id}` | イベント単件取得 | 200 + イベント |
| POST | `/api/events` | イベント作成 | 201 + 作成済みイベント |
| PUT | `/api/events/{id}` | イベント更新（全項目） | 200 + 更新済みイベント |
| DELETE | `/api/events/{id}` | イベント削除 | 204 No Content |

## 13. 変更管理プロセス

要件定義書確定後に変更が発生した場合、以下のプロセスに従う。

1. **変更提案**: 変更内容と理由を書面（メール等）で提出する
2. **影響分析**: 開発者がスケジュール・工数への影響を確認し回答する
3. **合意**: 双方が変更内容・スケジュールに合意する
4. **文書更新**: 要件定義書の改訂版を作成し、バージョン番号と改訂日を更新する

> 合意なしに実装を変更・追加することはしない。

## 15. 対象外（スコープ外）

- 通知・リマインダー機能

## 16. 用語集

| 用語 | 説明 |
|---|---|
| localStorage | ブラウザが端末内にデータを保存する仕組み。サーバー不要で動作するが、ブラウザのデータ消去により失われる場合がある。 |
| CRUD | Create（作成）・Read（参照）・Update（更新）・Delete（削除）の頭文字。データ操作の基本4操作。 |
| REST API | Web上でデータをやり取りするための標準的な設計方式。フロントエンドとバックエンドの通信に使用する。 |
| Docker / Docker Compose | アプリケーションの実行環境をパッケージ化する技術。`docker compose up` 一コマンドで複数のサービス（アプリ・DB）を同時に起動できる。 |
| PostgreSQL | オープンソースのリレーショナルデータベース。Phase 2 でイベントデータを永続保存するために使用する。 |
| React | Facebook が開発した JavaScript の UI フレームワーク。モダンなフロントエンド開発の標準的な選択肢のひとつ。 |
| TypeScript | JavaScript に型チェック機能を加えた言語。開発時のバグを早期に発見しやすくなる。 |
| Spring Boot | Java でバックエンドAPIを構築するためのフレームワーク。Phase 2 のサーバー処理に使用する。 |
| モーダル | 画面の前面に重なって表示されるダイアログウィンドウ。イベントの作成・編集フォームとして使用する。 |
