## 1. 非機能要件

### 1.1 レスポンシブ対応

| 画面幅 | デフォルト表示 | 備考 |
|---|---|---|
| PC（768px 以上） | カレンダービュー | タブでリストビューへ切替可能 |
| スマホ（767px 以下） | リストビュー | タブでカレンダービューへ切替可能 |

- ボタン・タップ領域は最小 44 × 44px を確保する
- スマホではモーダルを画面下からスライドアップ表示（ボトムシート形式）、PCではセンター表示

### 1.2 データ永続化

| フェーズ | 方式 | 注意事項 |
|---|---|---|
| Phase 1 | localStorage（ブラウザ内保存） | ブラウザのデータ消去で失われる可能性がある |
| Phase 2 | PostgreSQL（Docker コンテナ） | コンテナ停止でもボリュームにデータが残る |

### 1.3 パフォーマンス

- 通常の個人利用（イベント数 〜 数百件）において、表示・操作がスムーズに動作すること
- 画面の初期表示は体感で1秒以内を目安とする

### 1.4 セキュリティ

- 個人利用かつローカル環境での動作を前提とするため、認証・認可機能は実装しない
- Phase 2 のバックエンドは `localhost` のみからのアクセスを許可する（CORS設定）

## 2. テスト方針

### 2.1 テストの種類と担当

| 種類 | 内容 | 担当 | タイミング |
|---|---|---|---|
| 単体動作確認 | 各機能（作成・編集・削除・フィルター等）を手動で操作し確認 | 開発者 | 機能実装後、随時 |
| レスポンシブ確認 | ブラウザの DevTools でスマホ幅（375px想定）に切り替えて動作確認 | 開発者 | UI完成後 |
| 受け入れテスト | [機能要件定義書](functional-spec.md)の受け入れ条件（AC-01〜AC-12）を一覧表で確認 | 開発者・お客様 | 各フェーズ完了時 |

### 2.2 動作確認環境

| 種別 | 対象 |
|---|---|
| OS（PC） | Windows 11 / macOS |
| ブラウザ（PC） | Google Chrome 最新版 / Microsoft Edge 最新版 / Safari 最新版 |
| ブラウザ（スマホ） | iOS Safari / Android Chrome |

### 2.3 テスト対象外

- 自動テスト（ユニットテスト・E2Eテスト）は本プロジェクトのスコープ外
- 負荷テスト・セキュリティテストは個人利用のため実施しない

## 3. リスクと対策

| # | リスク | 影響 | 発生確率 | 対策 |
|---|---|---|---|---|
| R-01 | Phase 2 の技術習得（React / Spring Boot）に時間がかかる | スケジュール遅延 | 中 | Phase 1 完了後に技術調査期間を設け、難航する場合は早期に報告する |
| R-02 | Docker Desktop の環境構築トラブル | Phase 2 起動不可 | 低 | 事前に開発環境を整備し、動作確認済みの `docker-compose.yml` を提供する |
| R-03 | ブラウザ間の動作差異（特にドラッグ&ドロップ） | 一部機能が動作しない | 低 | 対応ブラウザ（Chrome / Safari / Edge 最新版）で都度確認する |
| R-04 | 仕様変更・追加要件の発生 | スコープ拡大・遅延 | 中 | 変更管理プロセス（セクション4）に従い、合意なしに実装変更しない |

## 4. 変更管理プロセス

要件定義書確定後に変更が発生した場合、以下のプロセスに従う。

```
1. 変更提案
   └─ 変更内容と理由を書面（メール等）で提出する

2. 影響分析
   └─ 開発者がスケジュール・工数への影響を確認し回答する（目安: 3営業日以内）

3. 合意
   └─ 双方が変更内容・スケジュール・費用（発生する場合）に合意する

4. 文書更新
   └─ 要件定義書および関連ドキュメントの改訂版を作成し、
       バージョン番号と改訂日を更新する
```

> **原則**: 合意なしに実装を変更・追加することはしない。

---

## 5. 制約・前提条件

- 動作環境はローカル開発環境（localhost）を前提とする
- Phase 2 の起動には Docker Desktop のインストールが必要
- 対応ブラウザ: Chrome / Safari / Edge（最新版）
- スマホは iOS Safari / Android Chrome を想定

|---|---|

| 外部カレンダー連携（Google Calendar 等） | 将来的な拡張候補 |

## 7. 用語集

| 用語 | 説明 |
|---|---|
| localStorage | ブラウザが端末内にデータを保存する仕組み。サーバー不要で動作するが、ブラウザのデータ消去により失われる場合がある。 |
| CRUD | Create（作成）・Read（参照）・Update（更新）・Delete（削除）の頭文字。データ操作の基本4操作。 |
| REST API | Web上でデータをやり取りするための標準的な設計方式。フロントエンドとバックエンドの通信に使用する。 |
| Docker / Docker Compose | アプリケーションの実行環境をパッケージ化する技術。`docker compose up` 一コマンドで複数のサービス（アプリ・DB）を同時に起動できる。 |
| PostgreSQL | オープンソースのリレーショナルデータベース。Phase 2 でイベントデータを永続保存するために使用する。 |
| React | Facebook が開発した JavaScript の UI フレームワーク。モダンなフロントエンド開発の標準的な選択肢のひとつ。 |
| TypeScript | JavaScript に型チェック機能を加えた言語。開発時のバグを早期に発見しやすくなる。 |
| Spring Boot | Java でバックエンドAPIを構築するためのフレームワーク。Phase 2 のサーバー処理に使用する。 |
| モーダル | 画面の前面に重なって表示されるダイアログウィンドウ。イベントの作成・編集フォームとして使用する。 |
| ドラッグ&ドロップ | 画面上の要素をマウスで掴んで移動させる操作方法。カレンダー上でイベントの日程変更に使用する。 |
| Flyway | SQLファイルでデータベースのスキーマ変更を管理するツール。変更履歴をバージョン管理できる。 |
| HMR | Hot Module Replacement の略。コード変更を保存すると、ブラウザをリロードせずに変更が即時反映される開発機能。 |
